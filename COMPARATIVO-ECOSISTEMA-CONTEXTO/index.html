    2. Capacidad por capacidad

    Capacidad Quién la tiene ContextMap
    Vault Obsidian navegable como grafo Obsidian + plugins ✅ con topología de árbol validada por test (0 sin padre, 0 colisiones, 0 wikilinks rotos) — nadie más impone esa garantía
    Brief portable para cualquier agente spec-kit, context7, repomix ✅ CONTEXT.md (+ .min, + secciones, + context_diff)
    Memoria viva multi-proyecto mem0, cognee, basic-memory ✅ BD personal + FTS5 + panorama
    Ingesta multiformato (chats, IDE, git, web, vídeo) deja-vu, markitdown, ragflow ✅ chats/IDE/git/sesiones/web/vídeo YouTube

    Humanización de la salida (nada de plantillas vacías) — ✅ único

    Memoria conversacional drop-in para apps mem0, letta ❌ (ContextMap es el mapa, no el runtime)

    3. Lectura estratégica

    Fortalezas diferenciales de ContextMap

    1. Gobernanza de la salida: es el único que trata el vault como artefacto verificable (test de topología, readiness, frescura, humanización). Los demás generan notas; ContextMap garantiza que el grafo no se corrompe.
    2. Portabilidad y coste cero: un archivo Markdown + un brief optimizado para prompt caching; sin claves, sin nube, sin cuotas.
    3. Determinismo: mismo repo → mismo vault. Ninguna de las alternativas basadas en LLM lo ofrece.

    Brechas reales (candidatas a roadmap, no a este plan)

    1. Temporalidad: graphiti modela cuándo cambió un hecho. ContextMap tiene diario y fechas, pero no un grafo temporal consultable.
    2. Feedback loop: no hay forma de que el agente corrija una clasificación y el sistema aprenda del ajuste. La cola revision:clasificacion es el primer eslabón; falta el ciclo de vuelta.
    3. Spec-driven: spec-kit/OpenSpec parten de especificaciones; ContextMap parte del código existente. Son complementarios, no sustitutos.
    4. Sync bidireccional: si el humano edita el vault, hoy no vuelve al mapa.

    4. Conclusión

    ContextMap no compite con Obsidian (es su formato de salida), ni con mem0/letta (esos viven dentro del runtime del agente), ni con spec-kit (esos parten de especificaciones). Su nicho es el mapa de contexto verificable y portable de un proyecto. La única capacidad del ecosistema que le daba ventaja competitiva y no tenía era la decisión calibrada (Jev); al replicarla localmente se cierra sin añadir dependencias, coste ni pérdida de determinismo.
